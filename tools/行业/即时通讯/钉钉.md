# 💬 钉钉 MCP

> 分类：行业 / 即时通讯
> 提供方：钉钉开放平台（open.dingtalk.com）
> 适用场景：群消息推送、告警通知、定时提醒、机器人播报

---

## 一、简介

钉钉 MCP 主要用于**自定义机器人 Webhook**，把 LLM / 自动化脚本产生的消息推送到钉钉群。
最常见的场景：定时推送通勤提醒、CI 失败告警、日报播报、监控告警等。

> 注意：本项目用的是**机器人 Webhook**（最简单），而不是完整的钉钉 OpenAPI。如需发私聊、操作工作台，请用 [Composio](../../技术/运维/Composio.md) 或自建 OpenAPI 接入。

---

## 二、核心能力

| 能力 | 说明 |
|------|------|
| 文本消息 | 推送纯文本 |
| Markdown 消息 | 支持加粗、链接、列表 |
| Link 消息 | 单条富文本卡片 |
| ActionCard | 交互式卡片（按钮 + 跳转） |
| FeedCard | 多链接消息 |
| @指定人 | @手机号 / @所有人 |

> 默认工具数：3

## 快速配置

> 直接复制以下片段到 `.env`，再补全你的 Key。完整模板见 [`.env.example`](.env.example)。
>
> 图例：`[REQUIRED]` 必填 · `[STRONG]` 强烈建议 · 其他可选

### 必填

```bash
DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxx  # 机器人 Webhook
```

### 强烈建议（生产环境）

```bash
DINGTALK_SECRET=SECxxxxxxxxxxxxxxxx  # 加签密钥
```

### 可选

```bash
DINGTALK_KEYWORD=通勤提醒  # 关键词校验
```

## 三、配置

### 3.1 创建自定义机器人

1. 打开钉钉 → 进入目标群聊
2. 群设置 → 智能群助手 → 添加机器人
3. 选择"自定义"机器人
4. 设置机器人名字 + 安全设置（推荐：**加签**）
5. 复制 **Webhook URL**（形如 `https://oapi.dingtalk.com/robot/send?access_token=xxx`）
6. 如果选了"加签"，复制**密钥**（SEC 开头的字符串）

### 3.2 环境变量

```bash
# 必填
DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxx

# 可选：加签密钥（强烈推荐开启）
DINGTALK_SECRET=SECxxxxxxxxxxxxxxxx

# 可选：消息关键词（开启"自定义关键词"校验时必填）
DINGTALK_KEYWORD=通勤提醒
```

### 3.3 安全设置三选一

| 方式 | 推荐度 | 说明 |
|------|:-----:|------|
| **加签** | ⭐⭐⭐⭐⭐ | 用密钥签名，最安全 |
| IP 白名单 | ⭐⭐⭐⭐ | 只允许特定服务器 IP |
| 自定义关键词 | ⭐⭐ | 消息必须包含关键词，最简单 |

> 三选一即可。**生产环境建议加签**。

## 四、使用示例

### 4.1 推送 Markdown 消息

```bash
curl -X POST http://localhost:8000/mcp/execute/dingtalk/send_markdown \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "🚗 通勤提醒",
    "text": "### 今日通勤\n\n- 距离：15.0 公里\n- 预计耗时：30 分钟\n- 出发建议：08:30\n\n[高德地图](https://www.amap.com)"
  }'
```

钉钉群里看到的：

```
🚗 通勤提醒
### 今日通勤
- 距离：15.0 公里
- 预计耗时：30 分钟
- 出发建议：08:30
高德地图
```

### 4.2 @指定人

```bash
curl -X POST http://localhost:8000/mcp/execute/dingtalk/send_text \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "@13800138000 请检查 CI 失败原因",
    "atMobiles": ["13800138000"]
  }'
```

### 4.3 ActionCard 交互卡片

```bash
curl -X POST http://localhost:8000/mcp/execute/dingtalk/send_action_card \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "部署审批",
    "text": "### 生产部署申请\n服务：order-service\n版本：v1.2.3",
    "buttons": [
      {"title": "通过", "actionURL": "https://ci.example.com/approve/123"},
      {"title": "拒绝", "actionURL": "https://ci.example.com/reject/123"}
    ]
  }'
```

## 六、加签算法

如果开启了"加签"安全设置，每次请求 URL 要带 `timestamp` 和 `sign` 参数。框架已自动处理，但了解原理有助排查：

```
1. timestamp = 当前时间戳（毫秒）
2. string_to_sign = f"{timestamp}\n{secret}"
3. sign = base64(hmac_sha256(string_to_sign, secret))
4. 最终 URL: webhook&timestamp=xxx&sign=base64sign
```

---

## 六、注意事项

- **频率限制**：每个机器人每分钟最多 20 条
- **消息大小**：单条不超过 20KB
- **超时**：Webhook 调用建议 `timeout_ms >= 5000`
- **关键词**：如果开启了"自定义关键词"，所有消息必须包含该词
- **撤回消息**：Webhook 模式不支持消息撤回
